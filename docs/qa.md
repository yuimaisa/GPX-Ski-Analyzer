# 検証結果

対象：合成GPXの解析、状態・速度表示、滑走選択、地図／グラフ／スライダー連動、入力エラー、レスポンシブ。

## 実施済み

- `npm run typecheck`、`npm run lint`、`npm run format:check` が成功。
- Vitest：2ファイル、25件成功。合成GPX、名前空間、複数トラック／セグメント、無効座標、時刻・標高欠損、重複・逆転時刻、不規則間隔、絶対／相対GPSスパイク、長い空白、短い／長い停止、滑走・上昇の反復、標高ノイズ、統計の整合性を確認。
- 合成サンプルは期待どおり4本。全体の滑走距離・時間は滑走別の合計に一致。
- ブラウザ用WorkerをバンドルしてVM内で実行。正常GPXの結果と不正GPXのエラーを確認。
- Next.js本番ビルド成功。ルート配信と `/GPX-Ski-Analyzer` サブパス配信をビルドし、アセット・Worker・サンプルのパスを確認。
- 開発サーバーを一時起動。HTML、Worker JS、サンプルGPXのHTTP 200とContent-Typeを確認し、終了。
- ソース内から指定された宣伝調の文言がなくなったことを検索で確認。
- Sitesへの非公開デプロイ成功。GitHubのoriginにはpushしていない。

## 修正した問題

- 急な折り返しの低速地点で滑走が過剰に分割される問題：継続中の滑走に低速側のヒステリシスを追加。
- Next.jsの静的出力でWorkerが未変換のTypeScriptとして配信される問題：esbuildでブラウザ用JSに独立バンドルし、バンドル実行テストを追加。
- ビルド後の型チェック・Lintが生成物を対象にする問題：生成ディレクトリとバンドルを除外。
- 空のGPXを形式エラーと誤認する問題：ルート要素の有無と有効地点数を分けて検証。
- グラフの開始地点が欠ける問題：最初の時刻付き地点を明示的に追加。

共有プレビューはNext.js向け引数を修正後も、環境の `relay could not open browser port 4173: timed out waiting for relay readiness` で接続できない。
